## 🔐 隐私电路详解

### **什么是隐私电路？**

隐私电路是一套数学约束系统，用于生成零知识证明（ZK Proof）。

**核心概念：**

```
┌─────────────────────────────────────────────────────────────┐
│  隐私电路 = 证明系统                                         │
│                                                             │
│  目标：证明"我知道某个秘密"，但不泄露秘密本身                │
│                                                             │
│  例子：隐私转账                                              │
│  ┌───────────────────────────────────────────────────┐    │
│  │ 我要证明：                                         │    │
│  │ ✅ 我有一个 Note（价值 100 ATOS）                 │    │
│  │ ✅ 这个 Note 在 Merkle Tree 里                    │    │
│  │ ✅ 我有对应的 Spending Key                        │    │
│  │ ✅ 我没有花过它（Nullifier 未使用）               │    │
│  │                                                    │    │
│  │ 但不告诉你：                                       │    │
│  │ ❌ Note 的具体内容                                 │    │
│  │ ❌ 我的 Spending Key                              │    │
│  │ ❌ 我要给谁                                        │    │
│  │ ❌ 金额是多少                                      │    │
│  └───────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

---

### **电路的工作流程**

```
用户操作：发送 50 ATOS 给 Bob

Step 1: 准备输入（钱包本地）
┌─────────────────────────────────────────┐
│ 私有输入（Private Inputs）：             │
│ • 我的 Note（金额、秘密、nullifier）     │
│ • 我的 Spending Key                     │
│ • Merkle Proof                          │
│                                         │
│ 公开输入（Public Inputs）：              │
│ • Merkle Root                           │
│ • Nullifier Hash                        │
│ • 接收方公钥                             │
└─────────────────────────────────────────┘
         ↓
Step 2: 运行电路（Prover）
┌─────────────────────────────────────────┐
│ 电路验证：                               │
│ ✅ Note 在 Merkle Tree 里               │
│ ✅ Spending Key 正确                    │
│ ✅ 金额守恒                              │
│ ✅ Nullifier 计算正确                   │
│                                         │
│ 输出：ZK Proof（一串数字）               │
└─────────────────────────────────────────┘
         ↓
Step 3: 提交到链上
┌─────────────────────────────────────────┐
│ 提交：                                   │
│ • ZK Proof                              │
│ • Nullifier Hash                        │
│ • 新 Merkle Root                        │
│                                         │
│ 不提交：                                 │
│ • Note 内容                             │
│ • Spending Key                          │
│ • 金额、接收方                           │
└─────────────────────────────────────────┘
         ↓
Step 4: 链上验证（Verifier 合约）
┌─────────────────────────────────────────┐
│ 合约验证：                               │
│ ✅ Proof 有效？                         │
│ ✅ Nullifier 未使用？                   │
│ ✅ Merkle Root 正确？                   │
│                                         │
│ 全部通过 → 交易成功                      │
└─────────────────────────────────────────┘
```

## 🚀 两种 Prover 部署方案

### **方案 A：浏览器 WASM Prover（当前使用）**

```
┌─────────────────────────────────────────────────────────┐
│ 优点：                                                   │
│ ✅ 无需额外服务器                                        │
│ ✅ 用户隐私最大化（证明在本地生成）                      │
│ ✅ 部署简单                                              │
│                                                          │
│ 缺点：                                                   │
│ ❌ 首次加载慢（下载 WASM，约 5-10MB）                    │
│ ❌ 证明生成慢（浏览器性能限制，约 5-30 秒）              │
│                                                          │
│ 启动方式：                                               │
│ • 不需要单独启动！                                       │
│ • 前端加载时自动下载 WASM                                │
│ • 用户点击"发送"时自动运行                               │
│                                                          │
│ 适用场景：                                               │
│ • 演示                                                   │
│ • 低频交易                                               │
│ • 注重隐私的用户                                         │
└─────────────────────────────────────────────────────────┘
```

### **方案 B：独立 Prover 服务（生产推荐）**

```
┌─────────────────────────────────────────────────────────┐
│ 优点：                                                   │
│ ✅ 证明生成快（服务器性能强，约 1-5 秒）                 │
│ ✅ 可以批量处理                                          │
│ ✅ 支持递归证明                                          │
│                                                          │
│ 缺点：                                                   │
│ ❌ 需要额外服务器                                        │
│ ❌ 用户需要信任 Prover                                   │
│                                                          │
│ 启动方式：                                               │
│ cd ~/atoshi-privacy-circuits                            │
│ npm run build:circuits                                  │
│ npm run setup                                           │
│ npm run start:prover                                    │
│                                                          │
│ 适用场景：                                               │
│ • 生产环境                                               │
│ • 高频交易                                               │
│ • 需要快速响应                                           │
└─────────────────────────────────────────────────────────┘
```
